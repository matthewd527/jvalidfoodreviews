# I JUST WANT TO EAT

A one-page companion site for [I Just Want To Eat](https://www.ijustwanttoeat.com),
Jean-Philippe Gerbi's New York and New Jersey food blog, running since July 2011.
It **refreshes itself from his blog** and needs no hand-editing.

It is deliberately not a copy of his site. His is a fifteen-year archive you
browse; this is a front door you scroll — masthead, ledger, the reviews, the
Michelin list, the recipes, the podcast, the beat. Everything links back to him.

## Run it locally

Double-click `index.html`, or serve it:

```bash
python3 -m http.server 8899
```

## Layout

```
index.html            markup (every number is a placeholder, filled at runtime)
css/style.css         Didone masthead, warm paper stock, one inverted section
js/main.js            reads window.SITE_DATA and renders every section
data/site.js            ← SCRAPED DATA. Regenerated by the job. Do not hand-edit.
data/history.json       one dated snapshot per run, for growth over time
assets/logo.jpg         his mark, for the favicon, the og:image and the About
scripts/update.py       the updater
.github/workflows/      the daily job
```

Data is a plain `window.SITE_DATA = {...}` assignment rather than JSON fetched at
runtime, so the page still works opened straight off the disk. A `fetch()` would
hit CORS on `file://`.

## How the refresh works

His blog runs on Squarespace, which will hand back any page as JSON if you ask
for it — append `?format=json`. No key, no OAuth, no login, nothing that expires.

Each run:

1. Walks `/post?format=json` back through the archive, 20 posts a page.
2. Classifies each post — where it is, what he ate, what kind of post it is.
3. Reads his four hand-built index pages: Michelin, recipes, podcast, Pick of
   the Month.
4. **Validates before trusting any of it** — see below.
5. Writes `data/site.js`, appends to `data/history.json`, commits, pushes.

`IJWTE_PAGES` controls how deep it walks; the default of 30 renders his most
recent 600 posts. The page still reports the true lifetime total (2,344 and
counting), read straight off the collection header, so the number is honest
about the archive even though the grid only carries a slice of it.

### It cannot corrupt the site

A run is **rejected outright**, leaving the previous `data/site.js` untouched
and exiting non-zero, if:

- fewer than 20 posts come back
- not one post comes back with a photograph
- the Michelin list comes back empty
- the post count has fallen by more than half since the last run

Photographs are referenced on his own CDN rather than copied into this repo.
Those URLs are stable and resize on demand (`?format=1000w`), so the repo stays
small and the images stay his.

### Classifying

Each post is scored, not raced: a word in the URL slug is worth more than the
same word in the title, which is worth more than one buried in the body. The
slug is keyword-stuffed for search, so it names the cuisine and the town even
when the headline is a tease. Racing the patterns in order instead filed *La
Brochette Steakhouse* under French, because "brochette" is a French word before
it is the name of a steakhouse.

Matching is on word boundaries, so `bar` does not match `barbecue` and `sake`
does not match `pancakes`.

Place falls back to the body only after the title and slug come up empty — a
Hoboken review mentions Manhattan in passing far too often to trust otherwise.
Posts about somewhere far from home are filed under **Away from home** rather
than dumped in the leftovers, and product and sponsored posts are separated from
restaurant reviews so they cannot drown the grid.

### Missing photographs

Posts old enough to predate his current CDN still carry an image URL, but it
resolves to Squarespace's 2 KB grey placeholder. It answers `200`, so only the
size gives it away — the updater does a `HEAD` on the ones that matter and
treats anything under 8 KB as absent.

That is not a rare edge case: **seven of his ten Picks of the Month and all
eighteen podcast episodes** have lost their artwork. Rather than print grey
rectangles, those Picks get a typographic archive card, and the episode list
drops its thumbnail column and runs as a numbered index.

## The contact form

**Write In** posts to [Web3Forms](https://web3forms.com), chosen because it needs
no account, no dashboard and no server: submissions arrive as plain emails and
the access key never expires. The free tier is 250/month.

**One-time setup — about a minute:**

1. Go to <https://web3forms.com> and enter the destination email address.
2. An access key (a UUID) arrives by email. Confirm it if prompted.
3. Open `index.html`, find `YOUR_WEB3FORMS_ACCESS_KEY`, and paste the key there.
4. Submit the form once to confirm it lands.

Until the key is in place the form refuses to send and says so on screen, rather
than swallowing a real tip into nothing.

Notes:

- **The key is public on purpose.** It only permits submissions to the address it
  was issued to and cannot read anything back, so it belongs in the HTML.
- A hidden honeypot field catches the bots that will find any public form;
  anything that fills it is dropped without a word.

## Instagram

His account is [@ijustwant2eat](https://www.instagram.com/ijustwant2eat/)
(~11.6K followers). The follower count is **off by default**; set `IG_HANDLE` to
switch it on:

```bash
IG_HANDLE=ijustwant2eat python3 scripts/update.py --dry-run
```

**Read this before relying on it.** There is no dependable free and hands-off
route:

- The anonymous endpoint needs no token and nothing expires, but it is metered
  hard per IP and will return `401`/`429` on plenty of days.
- The code treats that as normal: it keeps the previous numbers, flags them
  `stale`, and retries tomorrow from a different IP. The blog scrape is
  unaffected either way — the two run independently.
- It is also against Meta's terms of service, which is worth deciding on
  knowingly rather than by accident.

The dependable alternative is Meta's official API, which needs a Business or
Creator account and a one-time OAuth grant **from him**.

## Updating it by hand

```bash
python3 scripts/update.py --dry-run   # show what would change
python3 scripts/update.py             # do it
```

## Maintenance, honestly

Nothing here expires — no token, no card, no renewal. But Squarespace can change
the shape of that JSON payload without warning. When it does the job fails loudly
(red X, failure email) rather than writing garbage, and the fix is usually a small
path correction in `scrape_posts()`.

Budget one or two of those a year. Everything else runs itself.
